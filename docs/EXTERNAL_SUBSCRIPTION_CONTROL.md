# 外部系统控制订阅到期与流量重置

## 职责边界

外部网站为其管理的用户计算并设置准确到期时间，面板不推算购买月份、付款日或统一每月 1 日。到期停用和流量重置是不同操作。主控、Node 和部署脚本均不需要新增周期算法；本文说明既有 API 的正确调用及控制权交接，不代表生产用户已完成交接。

- `expire` 是 UTC Unix 时间戳（秒）。面板保存外部系统给定的时间，现有用户检查任务按该时间判断过期；保存精确时间不代表连接在该秒内同步断开。
- `data_limit_reset_strategy: "no_reset"` 禁止原生周期任务重置该用户流量，不禁止管理员明确调用重置接口，也不代表永不过期。
- 独立面板用户保留原策略：`day/week/month/year` 分别为 1/7/30/365 天，以创建时间或最近一次重置时间为锚点。这些不是外部系统的付费周期。
- 月度/多月额度、补偿天数、提前续费和新周期授予由外部系统决定。不能依据 `expire` 反推订阅起点，也不能把修改到期时间当作授予新流量。

## API

沿用管理员 Bearer Token 和用户归属校验；Token 只放服务端。新用户通过 `POST /api/user` 在其他必填字段之外明确传入 `expire` 和 `no_reset`。已有用户通过以下接口交接：

```http
PUT /api/user/example_user
Authorization: Bearer <server-side-token>
Content-Type: application/json

{"data_limit_reset_strategy":"no_reset"}
```

网站需要同时设置到期时间时，可以在同一个请求传入 `expire`（例如 `1894448467`，示例值，不可直接用于真实用户）。这不会重置 `used_traffic` 或新增流量重置日志；`data_limit` 是绝对上限（字节），不是充值增量。

`expire: 0` 表示不限时；省略或 `null` 保持原值。不要为了“同步”默认发送 0。仅更新到期时间不应调用 `POST /api/user/{username}/reset`。

保存后 `GET /api/user/{username}` 回读策略、到期时间和用量。既有 PUT 可能根据到期时间/上限调整用户状态，并安排后台 Xray/设备策略同步，不是纯元数据写入。

**交接前检查 `next_plan`。** 当前普通 PUT 的历史行为会清理未提供的 next_plan；`no_reset` 本身也不禁止另一个 next_plan 激活流程。外部管理用户不应同时挂有面板下一套餐，遇到已有 next_plan 应停止自动接管并由管理员明确处理，不能静默丢弃或恢复它。

## 从原生周期转交外部系统

1. 记录用户身份、策略、准确到期时间、额度、当前/累计用量及可用重置历史；确认归属及无 next_plan。
2. 持久化外部系统的交接记录，发送策略 PUT；不要先在本地标记接管成功。
3. GET 回读 `no_reset` 后核对交接前后用量与最近重置证据。正常采集可能使流量增加，不能要求前后数字完全相等。
4. 面板定时任务在获得写锁后重新检查策略。若 PUT 已提交，之前扫描到的旧候选会跳过；若定时重置先提交，后续 PUT 不会自动加回流量。发现计数下降或新重置记录必须走既有对账/人工处理，不能直接采用新零值覆盖付费基线。
5. 网络超时先回读当前状态；不要因为 PUT 或 GET 丢响应而调用 reset 补偿。只有完成远端核对和外部账本交接后，才由外部系统管理后续额度周期。

上述不是跨网站/面板的分布式原子事务。SQLite 已有锁内重查；其他数据库、跨进程及真实服务仍需部署环境验证。

## 显式重置与失败恢复

`POST /api/user/{username}/reset` 是破坏当前周期计数的明确操作，会记录重置前用量并清零当前量。该原版接口没有 operation_id 幂等回执，不可在超时后盲目重发。外部系统须保留发送前证据、持久化操作状态并回读核对，无法确认时停止自动写入；普通同步、到期停用和检查失败不能自动触发它。

`no_reset` 不移除已保存流量，不追溯恢复历史重置。客户用量恢复是独立的审计操作；不得通过恢复旧数据库覆盖新产生的用量，也不得批量清零。

## 变更与验收

本文的 expire/no_reset 调用不需要新增 API、数据库字段、迁移或面板周期算法，没有 UI/Node/scripts 运行时变化。无需为了本文重装或升级 Node。网站代码发布和已部署用户的受控策略交接仍是独立工作，不能把面板回归通过当作线上问题已修复。

已经发生的首次付款期内单条提前重置，另见[独立 v2 恢复接口](USAGE_CONTINUITY_V2.md)。该接口有主控运行时变化，需要发布新主控镜像；与上述既有控制方式分开验收，部署接口本身不代表允许自动恢复客户用量。

测试范围和未验收项见[验证记录](releases/external-reset-control-20261112.md)。
