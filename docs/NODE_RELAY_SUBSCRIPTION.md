# 中转订阅与客户端显示

开启中转只在原订阅条目上替换实际连接端点，保留别名、顺序、数量和用户凭据，不增加「Node 名称 (Relay)」。关闭中转后恢复原直连端点；其他 Node 和主服务器自己的业务条目不变。

## 地址与出口的区别

客户端的地址、端口列表示它实际连接的入口。经中转后必须指向所选来源服务器和分配的业务端口，不能仍写目标 Node 地址和 8443 却让客户端连接另一台服务器。最终出口由目标 Node 的原出口或住宅代理决定，名称仍可保留原目标名称。

入口未运行、匹配失败或歧义时，订阅保留原直连输出，不追加另一个中转副本；这不保证直连公网可达。`original_direct_hosts_preserved=true` 表示持久化 Hosts 未被覆盖，不表示同时输出直连和中转两份。

## Hosts 匹配规则

按入站标签、规范化原 Host 地址和所选业务端口精确匹配目标 Node，不按显示名称猜测，不解析 DNS 将不同域名认定为同一节点，不拆分混合多地址条目。原 Host 地址须与目标 Node 地址对应。多个原别名指向同一目标时逐项保留并改写端点，不增减数量。

无匹配原 Host、混合地址无法确定目标，或多个 Node 中转配置共用同一业务目的地时，保存返回 422，不应用新运行时或写库。旧歧义记录恢复时保留原输出并显示原因。UUID、HWID 独立凭据、REALITY 公钥、SNI、指纹、short ID 和传输覆盖参数仍由原订阅生成器提供；共享基础入站不应被输出过程修改。

## 客户端更新与验证

保存连接方式后刷新订阅，核对原名称与数量、真实入口地址/端口、实际联网和目标出口 IP。早期版本已导入的 Relay 条目可能留在客户端，应按客户端更新规则清理失效项或只删除旧的本地 Relay 条目，不删除用户或重装服务器。

切换主控来源、Node 来源和直连时分别刷新并核对；一个来源/目标失败不应冒充另一个目标的出口。适配与协议范围见[来源合同](NODE_RELAY_SOURCES.md)，更新要求不应沿用早期「Node 无需更新」的历史阶段结论。
