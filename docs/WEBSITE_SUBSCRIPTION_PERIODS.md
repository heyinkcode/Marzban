# 网站接入：按订阅管理 30 天流量周期

适用于任何对接 Marzban 的网站。功能仅对**显式接管**的账号启用，升级不会自动切换现有账号。未接管的账号仍按原来选择的每天、每周、每 30 天、每年或手动策略处理。网站自行确认付款、账号归属与何时开始新一期；Marzban 不接收付款或订单。

## 周期规则

| 操作 | 何时用 | 到期、额度与用量 |
| --- | --- | --- |
| `attach_period` | 首次接管已有用户，提供当前付费期的实际开始时间 | 保留当前到期、总额度、已用和累计；关闭该账号旧的定时清零。不接管无期限、无额度、待激活或有下一套餐的账号。 |
| `adjust_period` | 本期未到期时，按当前期号补偿时间、增加流量或同时调整 | 延期只改到期；加量只改总额度。都保留已用和累计。补偿只属于本期，有效到期以本期实际设置为准。 |
| `open_period` | 上一期实际到期、网站确认新一期已开始后 | 从新一期实际开始起算 30 天（2,592,000 秒），总额度设为新一期的基础额度。本期用量归零一次，上一期用量仍计入历史累计；不继承上一期的额外时间或额度。 |

即使到达默认的 30 天或补偿后的实际到期时间，面板也**不会自行开启下一期或清零**。如果用户提早续费，网站应保留订单结果，等实际生效时再调用 `open_period`；不能把付款时间直接当作下一期开始。若未开启新一期，原到期限制仍生效。开启下一期不会解除管理员设下的禁用。

## 权限与能力检测

使用 [管理员令牌](WEBSITE_ENTITLEMENT_API.md#接入前准备)，只由可信网站后端通过 HTTPS 调用。三种周期操作的预览和提交均需超级管理员（`is_sudo`）。建议把凭据放在执行写入的受控后端，为每个请求检查订单、账号与允许的动作；不要把令牌、密码或完整订阅链接暴露给浏览器、客户端或日志。普通管理员只能读取其名下用户，不能写入订阅周期。

先调用 `GET /api/user/{username}/entitlement`。确认 `subscription_period_capability` 为 `website-subscription-period-v1`，且 `can_manage_subscription_period` 为 `true` 再开启写入。路径中的用户名须 URL 编码。已接管账号的 `state.subscription_period` 包含：

- `period_id`：当前期 UUID；补偿必须使用它。
- `starts_at` 和 `default_ends_at`：UTC Unix 秒；后者是未补偿的 30 天边界，**非实际到期**。实际到期读 `state.expires_at`。
- `mode`：`monthly`（没有本期额外设置）或 `manual`（实际到期不同于默认边界，或有额外额度）。
- `base_quota_bytes` 和 `added_bytes`：字节数字符串；当前实际额度和已用读 `state.quota_bytes`、`state.used_bytes`。接管时用当时额度作为本期基准，不猜测接管前是否有增额。

已接管账号底层 `reset_strategy` 为 `no_reset`，仅表示旧定时器已关闭，不代表新一期不按 30 天算。未接管账号没有 `state.subscription_period`；仅在普通编辑中选择「手动设置[按订阅]」不会自动接管。

## 调用顺序

下列命令 JSON 均用于 `POST /api/user/{username}/entitlement/preview`，返回 `guard`、变更前后的 `before` 和 `after`，不写数据。下列时间和期号只是示例；实际开始不能晚于面板当前时间。额度以正整数字符串传入；时间用整数秒。

1. 首次接管已有的当前期（请先确认现有到期、额度与真实订阅一致）：

   ```json
   {"action":"attach_period","period_id":"11111111-1111-4111-8111-111111111111","starts_at":1893456000}
   ```

2. 当前期延期并加 10 GiB。只延期可省略 `extra_bytes`；只加量可省略 `expires_at`：

   ```json
   {"action":"adjust_period","period_id":"11111111-1111-4111-8111-111111111111","expires_at":1896652800,"extra_bytes":"10737418240"}
   ```

3. 本期实际到期时开启下一期（新期号、实际开始、100 GiB 基础额度）。下一期默认结束为 `1899244800`：

   ```json
   {"action":"open_period","period_id":"22222222-2222-4222-8222-222222222222","starts_at":1896652800,"quota_bytes":"107374182400"}
   ```

核对预览后，调用 `POST /api/user/{username}/entitlement/operations`，请求体包括 `operation_id`（为每次业务动作保存一个新 UUID）、与预览**完全相同**的 `command`、原样复制的 `guard`，以及布尔型 `confirmed`（接管和开启新一期必须为 `true`）。成功返回已持久化的回执。清零动作的 `reset_id` 指向历史流水。

响应丢失或请求超时时，先 `GET /api/user/{username}/entitlement/operations/{operation_id}` 回查；需要重试时用原编号和原请求体，不能换号再开期。相比固定回执，概览可以反映后来新增的流量。一个账号的同一期号不能重复开期，即使换了操作编号。

## 错误与兼容

接口同 [用户到期时间与流量 API](WEBSITE_ENTITLEMENT_API.md) 返回 `detail.code`。典型错误：

| 状态 / code | 处理 |
| --- | --- |
| `401`、`403 permission_denied` | 核对令牌和权限；不退回旧接口。 |
| `409 subscription_period_start_invalid` | 开始时间不得早于上一期实际到期、晚于面板现在；新一期也不得已全部过去。 |
| `409 subscription_period_changed` / `subscription_period_id_used` | 补偿指向旧期或新期号已使用。读概览、回执及同一期订单；不要把旧期补偿自动转给新期。 |
| `409 subscription_period_not_active` | 本期已到期，不能用本期补偿接口改写。需单独核对订单和开期条件。 |
| `409 entitlement_changed` / `operation_conflict` | 当前状态变化，或操作编号已绑定其他请求；先回查，再按最新状态决定是否重新预览。 |
| `409 next_plan_conflict` | 先核对现有下一套餐；接管不删除或激活它。 |

已接管账号的旧延期、增额、续期/重置接口（包括机器人旧重置入口）、普通编辑中的套餐字段与下一套餐写入均不作为旁路；编辑备注或读取账号仍可按原权限使用。目标范围内含已接管账号时，旧「批量重置」全部拒绝，避免部分清零。核实后的误重置补回仍单独走超级管理员接口；不能补回正常开期产生的流水。

## 上线验证

先在测试账号验证只读预览、普通管理员拒绝、本期延长/增额不清零、提早开启被拒绝、原编号重试不重复清零；再接入真实订单。迁移新增期号记录，不改原用户；有期号记录时拒绝降级删除该表，不要在旧镜像上继续写入已接管账号。Node 和安装脚本不需配套修改。
