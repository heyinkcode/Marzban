# 用户时间与流量

新版主控镜像已发布，生产实例需单独升级与验收。[镜像和验收说明](releases/native-user-entitlement-20261127.md)。

适用于独立部署的 Marzban 主控，不要求接入任何网站、支付服务或 Node 扩展。管理员在「编辑用户 → 时间与流量」操作，也可通过既有管理员令牌调用下列接口。

| 操作 | 到期时间 | 总额度 | 当前已用、历史累计 |
| --- | --- | --- | --- |
| 延长时间 | 改为更晚的日期 | 不变 | 都不变；用完的账号仍限流 |
| 增加额度 | 不变 | 加上指定流量 | 都不变；已到期的账号不会因此恢复 |
| 重置本期用量 | 不变，或明确指定更晚的日期 | 不变 | 本期归零；原用量仍计入历史累计 |
| 补回误重置（超级管理员） | 不变 | 不变 | 把最近一条经核实的误重置用量补回本期，之后产生的用量保留，历史累计不重复增加 |

新用户默认「仅手动重置（按订阅）」（`no_reset`）。升级不替换已有规则。「每 30 天（旧规则）」（`month`）仍按旧调度运行，不是每月 1 日，也不会只因延期同步移动计量周期。若合同要求延期不换额度、只在明确开新计量期时清零，请逐账号确认是否应改用 `no_reset`。已有「下一套餐」仍按用户原先设定执行；关闭周期重置不代表关闭下一套餐。

## 面板操作

1. 选中用户，打开「时间与流量」。如果原编辑表单还有未保存内容，先处理这些编辑。
2. 选择操作并填写所需信息。面板显示本机时区，增加额度以 GiB 输入（1 GiB = 1,073,741,824 字节）。
3. 点击「预览变更」，核对到期、总额度、已用和剩余。重置和补回还须勾选确认再保存。
4. 如果网络中断且结果未知，用面板的原编号重试。不要重复发起新操作。计量仍在进行，保存回执反映的是提交时的实际计数。

误重置补回仅处理当前可使用账户的最近一条、尚未补回的正数重置记录。旧历史不一定记了发起人和来源；系统不能替代管理员核实该记录仍属当前周期。明确由本功能发起的重置不能走补回。达到或超过额度、已过期、非活跃、存在下一套餐等情况不自动补回。该功能不判断付款、不自动改策略，也不批量翻查或修改客户历史。

## API

网站从后端读取用户或在付款后设置权益，请参照[网站接入指南](WEBSITE_ENTITLEMENT_API.md)（鉴权、字段、可复制的请求与错误处理）。

使用 `POST /api/admin/token` 签发的 Bearer 令牌；普通管理员只能操作自己管理的用户，补回限制为超级管理员。路径中 `username` 必须进行 URL 编码。

| 方法与路径 | 用途 |
| --- | --- |
| `GET /api/user/{username}/entitlement` | 只读当前流量、到期、规则和最近重置 |
| `POST /api/user/{username}/entitlement/preview` | 只读预览，返回 `guard` 和 `before`、`after` |
| `POST /api/user/{username}/entitlement/operations` | 按预览提交一次操作，返回持久化回执 |
| `GET /api/user/{username}/entitlement/operations/{operation_id}` | 读取同账号原始回执，不执行操作 |

预览的 JSON 体任选一条（`expires_at` 是未来 UTC Unix 秒，下例时间值仅示意；字节量是十进制字符串）：

```json
{"action":"extend","expires_at":1893456000}
```
```json
{"action":"add","extra_bytes":"10737418240"}
```
```json
{"action":"renew"}
```
```json
{"action":"restore","reset_id":26,"reason":"已核实该次重置为当前计量期内的误操作"}
```

提交时沿用预览的 `command`，以一次操作一个 UUID，填入返回的 `guard`。重置或补回须显式传 `confirmed: true`。

```json
{
  "operation_id":"23ddf502-ed02-4d51-81c5-efacf59108ac",
  "guard":"<从预览响应原样复制>",
  "command":{"action":"add","extra_bytes":"10737418240"},
  "confirmed":false
}
```

如果提交超时，先查该 UUID 的回执；若无回执，可原样重发同一 UUID 和请求体。相同 ID 不重复写，不同请求复用 ID 返回冲突。用户到期、额度、策略、状态、下一套餐、最近重置或最近原生操作变动时，过时预览可能被拒绝；以实际错误为准，重新只读预览核对。无限时间不能走「延长时间」，无限额度不能走「增加额度」。清零请用明确的重置操作。

本修复的 `PUT /api/user/{username}` 只传 `expire` 或只传 `data_limit` 不清流量；省略 `next_plan` 保留，显式传 `next_plan: null` 才移除。旧 reset API 仍在；调用者不能把它当成普通延期接口。既有 [v1](USAGE_CONTINUITY.md) 和 [v2](USAGE_CONTINUITY_V2.md) 历史恢复合同不变。

## 升级和验证

仅更新主控。迁移 `e567fa89bc01` 建立追加写入的操作回执表，不重写现有账号和日志。升级前备份数据库和配置；表有回执时禁止降级删除。不能为回滚而删除回执、强行回退恢复记账或覆盖已更新的业务数据库。Node、安装脚本与 Xray 版本不变。

用测试账号验证：用完后只延期仍限流；加额度的已用和到期不动；明确确认才归零且历史总量不变；同 UUID 原样重试不重复入账；升级前后的已有重置策略、下一套餐一致。测试不要使用生产客户。
