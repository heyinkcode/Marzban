# 中转设置与部署

支持两种单跳路径，服务器可部署在任意地区：

- 客户端 → Marzban 主服务器的中转入口 → 目标 Node 业务入站 → 目标出口。
- 客户端 → 源 Node 的中转入口 → 目标 Node 业务入站 → 目标出口。

原生出口与住宅代理由目标 Node 决定。来源服务器自己的业务出口不参与透明转发；Marzban Web/API、REST/RPyC 控制连接与用户数据是不同通道。

## 设置步骤

1. 先保存目标 Node 并确认原控制连接及业务入站，再打开该 Node 的「连接方式 → 管理」。原名称、地址、证书、控制/API 端口、倍率和子节点表单不变。
2. 选择「通过中转服务器」和来源：主面板服务器或另一台已连接且支持中转能力的 Node。
3. 「中转入口地址」填写所选来源的直连公网 IPv4 或 DNS-only 域名，不填目标 Node 地址、面板网页 URL、CDN 代理地址、协议前缀或路径。
4. 选择目标业务入站和自动/手动入口端口。自动分配从 18443 起；手动范围 1024–65535。控制/API 端口不是目标业务端口。
5. 保存后仅放行来源的所选业务 TCP 端口，并确保来源能访问目标入站；默认使用 host 网络，自定义 bridge 容器还须正确映射端口。程序不自动修改云安全组或防火墙。
6. 刷新客户端订阅，仍选择原名称的目标条目。地址/端口显示真实中转入口，最终公网出口应为目标 Node 或其住宅代理；不会新增一个 Relay 条目。

一个目标配置一个来源和一个业务入站；同一来源可转发多个目标。端口不能与业务、面板、控制/API 和已分配监听冲突。当前分配保守地跨来源全局去重，不在多个来源复用同一端口。禁止自己转发给自己、同控制地址源/目标及配置环路；不同域名别称不会通过 DNS 自动识别为同一台机器。

## 协议与影响范围

产品选择器及订阅目前接入 VLESS TCP/RAW REALITY，使用固定 Xray v26.3.27 的独立 TCP 转发进程，不终止 REALITY。它不改用户 UUID、SNI、公钥、short ID 或设备凭据；认证和账号用量仍在目标 Node，来源机器网卡及供应商流量仍可能计费。

不提供独立 UDP 监听，不支持把任意原生 UDP 自动变成 TCP。只有被客户端/目标协议封装进 TCP 隧道的流量可随该连接转发，实际 UDP/DNS 能力还取决于目标协议和出口。不是多跳链式选择，也不是所有 TCP/UDP 协议均已实现或验收。

保存中转配置不重启来源或目标业务核心；每个来源独立转发进程的完整快照变化，可能短暂中断该来源的其他中转会话。目标看到的网络来源是中转服务器，不承诺保留客户端真实 IP。监听已就绪不代表目标可达、REALITY 握手成功或网速提升。

## 配对更新与回退

主控需要支持来源选择，承担中转的源 Node 需要 `managed-node-relay-v1`；仅作目标的已配对 Node 不因此要求新来源能力。已有 Fork 先更新承担来源的 Node、确认连接和能力，再更新主控；不重复 adopt/install、不换证书或原控制端口、不删卷。其他出口检测等新功能按各自能力要求升级。

切回直连后保存并刷新客户端订阅，应恢复原条目端点并清理旧来源监听。回退旧主控前先导出/备份并清空不受支持的 Node 来源设置，确认源空快照；不能把仍有 Node 来源字段的数据库直接交给只认识主控来源的旧版本。
