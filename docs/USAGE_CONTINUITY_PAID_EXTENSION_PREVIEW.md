# 已续费额度延长期内单次提前重置补回（未发布）

这是本地联调合同，不是已发布 API 或可直接在生产执行的功能。v1/v2 恢复入口保持原状；未改 Node、安装脚本、Xray 或数据库迁移。

## 接口草案

以下均要求 sudo 管理员，禁止缓存：

- GET /api/usage-continuity/paid-extension-v1/users/{username}/preview：只读输出身份与历史指纹，范围为 panel_state_only，不证明付款。
- POST /api/usage-continuity/paid-extension-v1/users/{username}/repairs：独立 reason 为 restore_renewed_allowance_during_extension。请求包含 operation_id、evidence_sha256、expected、prior_corrections_sha256 和 paid_extension_evidence；配额字节使用十进制字符串，时间使用六位小数的 UTC Z 格式。
- GET /api/usage-continuity/paid-extension-v1/repairs/{operation_id}：只读原回执，不允许把其他版本回执当作本合同回执。超时、404 或 5xx 不表示操作未提交，原编号不可重发或换号。未发送的准备记录和可能已发送的记录必须区分。

## 约束

- 业务方必须独立确认已付款续费的额度周期、实际服务延长期仍沿用同一额度、已确认的续费重置边界、本次异常流水、以及没有后续付款或冲突任务。在发起主控操作前必须用网站持久化围栏阻止同一订阅的订单、续费和操作竞争；失败或结果未知只读原回执。
- 主控在 SQLite 写锁内重读账号身份、额度、到期、重置策略、下一套餐、完整重置历史和既有纠偏指纹。只处理紧接已确认续费边界的最新提前重置，较早补回记录留存；历史、身份和已用量基线不匹配时停止。补回达到额度或服务期已结束时拒绝。
- 只增加实时本期已用并原子追加同一重置流水的回执。累计用量、历史重置日志、额度、服务有效期、策略和用户状态不改。网站已保留重置前计数时，只应通过正常采集认领其后的新增量。
- 接入网站围栏、回执确认与计量回读必须一并验证，通过后再单独走 no_reset 交接；禁止把局部测试或排队当作生产恢复。

## 发布门槛

本地 SQLite 授权、原子增加、幂等及拒绝测试，以及配套网站的仿真 PostgreSQL + 面板替身验证，仅证明本地行为。正式发布前复核生产目标新鲜状态、发起方身份与原始支付凭证、快照及备份；测试未知调用结果的人工处理流程。没有新付款或恢复期限内新证据时也不能跳过网站授权。主控候选镜像和网站限定账号恢复工具应分别进行部署验收，再允许个案写入。
